# Raceline optimization

Testing methods for computing an optimal raceline from a racetrack, using real track data plus the TUM
minimum-curvature/shortest-path/min-time optimizer.

## What's here

- `track_data/f1tenth_scale_tracks/` — clone of [f1tenth/f1tenth_racetracks](https://github.com/f1tenth/f1tenth_racetracks). Real-world
  track layouts (Spielberg/Red Bull Ring, Monza, Silverstone, etc.) as `<Track>_centerline.csv`
  (`x_m, y_m, w_tr_right_m, w_tr_left_m`) plus an already-optimized `<Track>_raceline.csv` for comparison, a map
  PNG+YAML, and (for some tracks) a DonkeySim waypoints file.
- `track_data/occupancy_maps/` — clone of [CPS-TUWien/f1tenth_maps](https://github.com/CPS-TUWien/f1tenth_maps). ROS `map_server`-style
  occupancy-grid maps (PNG+YAML), not centerline CSVs — would need centerline extraction first (see the `pure_pursuit`
  lab's `tools/extract_centerline.py` approach: threshold to a free-space mask, skeletonize, prune to the main loop)
  before it could feed the TUM pipeline below. Its `costmaps/` folder also ships its own shortest-path/spline costmap
  generator — a second, independent method worth testing later, not wired up yet.
- `tum_optimizer/` — clone of
  [TUMFTM/global_racetrajectory_optimization](https://github.com/TUMFTM/global_racetrajectory_optimization) (the tool
  `track_data/f1tenth_scale_tracks`' own `_raceline.csv` files were generated with — same CSV header format, same
  `<uuid>` / `<git-hash>` comment lines at the top of the output). Supports four objectives via `main_globaltraj.py`'s
  `opt_type`: `shortest_path`, `mincurv`, `mincurv_iqp` (iterative refinement of mincurv), `mintime`.

## Environment

Python 3.10 in a dedicated venv (`tum_optimizer/.venv`), **not** system Python 3.14 — numpy/scipy
don't ship wheels that new. Homebrew's `python@3.10` provided the interpreter:

```
brew install python@3.10   # if not already present
cd tum_optimizer
/opt/homebrew/opt/python@3.10/bin/python3.10 -m venv .venv
source .venv/bin/activate
pip install "setuptools<81" numpy matplotlib trajectory_planning_helpers "scipy==1.13.1" scikit-learn casadi quadprog
```

Two things needed pinning away from `pip install -r requirements.txt` (which targets Python 3.7 and doesn't resolve
on anything newer):
- **`scipy` must be `1.13.1`, not latest.** Latest scipy's `scipy.sparse.linalg` wheel fails to `dlopen` on this
  machine's very new macOS/arm64 combo (`_propack` extension: "section `__DATA/__thread_bss` has a zero-fill section
  type, but offset field is not zero"). 1.13.1 loads fine.
- **`setuptools<81`** — `pkg_resources` (still imported by `main_globaltraj.py` and by `trajectory_planning_helpers`)
  was dropped from setuptools 81+.

Run everything with `MPLBACKEND=Agg` unless you want interactive plot windows to pop up and block.

## Code patches (all local, not upstreamed)

1. **`main_globaltraj.py`: dependency version check removed.** It called
   `pkg_resources.require(open('requirements.txt').readlines())`, which hard-fails on any version newer than the
   Python-3.7-era pins. Replaced with a comment; versions were checked manually instead (see above).
2. **`trajectory_planning_helpers/spline_approximation.py` (in the venv's site-packages): `dist_to_p` patched to
   flatten `interpolate.splev()`'s output before `scipy.spatial.distance.euclidean()`.** Modern scipy's
   `_validate_vector` no longer auto-`.squeeze()`s (it used to, silently, in the scipy version this package was
   written against), so a `(2,1)`-shaped list-of-arrays now raises `ValueError: Input vector should be 1-D` instead of
   being squeezed to `(2,)`. One-line fix: `s = np.asarray(s).flatten()`. **This lives in `.venv/`, so it's lost if the
   venv is recreated** — reapply it if you rebuild the environment (search `spline_approximation.py` for `dist_to_p`).
3. **`main_globaltraj.py`: `mincurv_iqp` branch updated for a newer `trajectory_planning_helpers` API.** The pinned
   `tph==0.76` (repo's `requirements.txt`) had a 3-arg `iqp_handler`; the installed `tph==0.79` needs
   `spline_len`/`psi`/`kappa`/`dkappa` of the reference line as extra args and returns 7 values instead of 3. Patched
   to compute those (via `tph.calc_spline_lengths` + `tph.calc_head_curv_an`, matching what `iqp_handler` does
   internally on each iteration anyway) and unpack the full tuple.

None of these change the optimization math — they're compatibility shims for running 2020-era pinned code on a 2026
interpreter/toolchain.

## F1Tenth vehicle profile (`params/racecar_f1tenth.ini`)

The shipped `params/racecar.ini` is a full-size Formula-E car (width 2.0 m, mass 1200 kg, `v_max` 12 m/s). Rather than
guess F1Tenth-scale numbers from scratch, they were **reverse-engineered from `track_data/f1tenth_scale_tracks`' own shipped
`Spielberg_raceline.csv`** (generated by this same tool, presumably by the track repo's maintainers with a real
F1Tenth vehicle profile that isn't published) by reading off `vx_mps`/`ax_mps2`/`kappa_radpm`:

| quantity | observed in `Spielberg_raceline.csv` | used in `racecar_f1tenth.ini` |
|---|---|---|
| `v_max` | 8.0 m/s (hard cap) | 8.0 m/s |
| ax, accel (motor-limited) | ~3.35 m/s² | 3.4 m/s² (`ax_max_machines_f1tenth.csv`) |
| ax, braking (tire-limited) | ~5.46 m/s² | 5.5 m/s² (`ggv_f1tenth.csv`) |
| ay (tire-limited) | ~10.0 m/s² | 10.0 m/s² (`ggv_f1tenth.csv`) |

`width`/`length`/`mass`/wheelbase use typical 1/10 RC-chassis values (wheelbase `lf=0.15875 + lr=0.17145 = 0.330 m`,
matching f1tenth_gym's default vehicle — see [[f1tenth-docker-setup]] memory). `width_opt` (safety margin used during
optimization) is set to 0.50 m, comfortably inside the ~2.2 m track width these tracks actually have, so the optimizer
has real room to work with. The `mintime` powertrain/tire parameters are rough placeholders (no motor spec sheet or
tire test data available) — **`mintime` results on this profile are not trustworthy**; `shortest_path`/`mincurv`/
`mincurv_iqp` don't depend on them.

**Validation:** re-running the exact pipeline on `Spielberg.csv` with this profile reproduced the track repo's own
result closely — track length 338.77 m vs. their 338.13 m (+0.2%), estimated laptime 44.65 s vs. their ~45.05 s
(-0.9%) — good evidence the reverse-engineered profile is close to whatever they actually used.

## First test: three methods on Spielberg (Red Bull Ring)

Track file: `inputs/tracks/Spielberg.csv` (copied from `track_data/f1tenth_scale_tracks/Spielberg/Spielberg_centerline.csv`).
Vehicle profile: `racecar_f1tenth.ini`. Outputs saved per-method in `tum_optimizer/outputs/`
(`Spielberg_<method>.csv`, since `main_globaltraj.py` otherwise always overwrites `traj_race_cl.csv`).

| method | laptime (est.) | path length | max \|curvature\| | mean speed |
|---|---|---|---|---|
| `shortest_path` | 46.86 s | 330.86 m | 2.624 rad/m | 7.42 m/s |
| `mincurv` | 44.65 s | 338.77 m | 0.785 rad/m | 7.71 m/s |
| `mincurv_iqp` | **42.15 s** | 330.20 m | **0.357 rad/m** | **7.87 m/s** |

Matches the theory cleanly:
- `shortest_path` cuts the geometrically shortest line through corners, which means sharp apexes (highest curvature by
  far) — the car has to slow the most for those, despite the path itself being short.
- `mincurv` smooths curvature a lot (2.6 → 0.79 rad/m) by using more of the track width, at the cost of a longer path
  (+8 m) — net win on laptime.
- `mincurv_iqp`'s iterative refinement gets the best of both: path length back down near `shortest_path`'s (330.2 m)
  *and* curvature down further still (0.36 rad/m) by re-linearizing around its own solution each iteration. Took 195
  iterations to converge on this track/profile (oscillating curv_error, terminated once it dropped under the 0.01
  rad/m tolerance) — clearly the best of the three here, at the cost of runtime.

To reproduce or try another track/method: edit `file_paths["track_name"]` and `opt_type` near the top of
`main_globaltraj.py`, drop a `<Track>_centerline.csv` from `track_data/f1tenth_scale_tracks/<Track>/` into `inputs/tracks/` (rename
without the `_centerline` suffix, or point `track_name` at whatever you name it), then:

```
cd tum_optimizer && source .venv/bin/activate
MPLBACKEND=Agg python main_globaltraj.py
```

Result lands in `outputs/traj_race_cl.csv` (format: `s_m; x_m; y_m; psi_rad; kappa_radpm; vx_mps; ax_mps2`).

## Not done yet / possible next steps

- `mintime` (true time-optimal, needs CasADi/IPOPT) — runs, but not validated against real F1Tenth powertrain/tire
  data; would need at least a rough motor torque curve and tire friction coefficient to be meaningful.
- `track_data/occupancy_maps`' own costmap-based shortest-path/spline generator (`costmaps/`) — a second, independent method, not
  wired up.
- Only tested on Spielberg so far; `track_data/f1tenth_scale_tracks` has 22 tracks total, all in the same format.
